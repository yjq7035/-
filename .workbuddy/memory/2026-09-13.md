# 2026-09-13

## 修复：微信小游戏启动时 "jsbridge not ready" 警告
- 现象：开发者工具启动报 `[jsbridge] invoke getSystemInfo fail: jsbridge not ready`，堆栈全在 WAGame.js 引擎内部，由 `game.json` 的 `deviceOrientation` getter 触发 `getSystemInfo`（启动竞态）。
- 修复：`game.js` 入口改为延迟初始化——`canvas/ctx/windowInfo` 声明为模块级 `let`，移到 `boot()` 内赋值；启动用 `requestAnimationFrame(boot)` 推迟到首帧（jsbridge 已就绪）；系统信息优先用 `wx.getWindowInfo()`，避开已废弃的 `wx.getSystemInfoSync()`（含 deviceOrientation getter 路径）。
- 结论：引擎内部那条 deviceOrientation 警告属 devtools 已知良性首帧提示，真机一般不出现；本次修复消除了"我们代码顶层同步读 wx"的隐患，更健壮。

## 模拟器鼠标点击失效排查（图形塔防）
- 结论：代码问题，非模拟器不支持。项目是微信小游戏（game.json + wx.createCanvas），模拟器跑根目录 game.js。
- 根因1：getTouchPos 读 touch.x/touch.y，微信 Touch 只有 clientX/clientY → 坐标 undefined，所有命中判定 false。
- 根因2：touchend 时 e.touches 已清空，getTouchPos 取 e.touches[0] 抛错，拖放落不了槽。
- 修复：getTouchPos 统一读 clientX/clientY（兼容旧 x/y），touchend 改从 changedTouches 取；initEvents 增加 mousedown/mousemove/mouseup 回退，模拟器与PC浏览器均可用。

## 代码整合：删除 js/ 网页版
- 用户确认只保留根目录 game.js（微信小游戏入口，模拟器跑的就是它），删除 js/ 目录 + index.html。
- 同步把上轮在 root game.js 加的 mouse 事件回退移除，initEvents 只留 touchstart/touchmove/touchend，getTouchPos 只处理 clientX/clientY + changedTouches。模拟器功能不变。
- node --check game.js 通过；game.js 无 import/require，无对 js/ 的残留引用。

## 点击商店槽崩溃根因+修复（图形塔防）
- 现象：点商店槽后正规崩溃、怪物卡死。
- 根因：drawDragPreview 第303行  —— 右侧 ctx 解析成本行刚声明的局部 const（TDZ），非全局 ctx → ReferenceError。该异常在 loop() 内 update/draw 抛出，导致末尾 requestAnimationFrame(this.loop()) 不再排程，游戏循环停。
- 修复：删掉该行（this.ctx 从未被赋值，其它 draw* 都用全局 ctx），drawDragPreview 直接用全局 ctx。
- 验证：用 node mock（wx/canvas/ctx/rAF）跑了一遍，覆盖 boot/怪物移动/刷新/拖拽/真实槽位放塔/重复点击/游戏结束，全部无崩溃。临时测试器 _test_harness.js 已删。
- 观察：towers 放置后无攻击逻辑（update 未遍历 this.towers 开火），塔是装饰性的，敌人不会被塔打——功能性缺口，非崩溃。

## 代码拆分：单文件 game.js 拆为多模块（图形塔防）
- 用户要求把单文件 game.js 按功能分散到多个 js。微信小游戏原生支持 CommonJS require。
- 结构：根 game.js=入口（全局 canvas/ctx/windowInfo + boot() + new Game）；src/ 下：config.js（数据表/布局/数值）、geometry.js（路径几何纯函数）、enemy.js（敌人工厂+更新）、wave.js（波次生成）、tower.js（塔工厂+造价）、renderer.js（全部 draw*）、input.js（触摸处理）、game_core.js（Game 类协调）。
- 关键改动：原 draw* 用全局 ctx、方法用 this；拆出后统一传 game 实例（game.ctx/game.canvas）。drawDragPreview 保留上一轮的 TDZ 修复。
- 验证：重建 node mock 测试器（wx/canvas/ctx/raf），18 项断言全 PASS（boot/怪物移动/拖放放置/刷新/重复点击/敌人到终点扣血/游戏结束）。修复 enemy.js 漏 import getPathLength 的 bug。临时测试器已删。
- 行为不变：坐标/数值/点击判定与原版一致。塔不攻击敌人的功能性缺口仍然存在（未改逻辑）。
