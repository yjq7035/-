## 修复「属性面板文字溢出」+「图签点卡片弹不出详情」

两个报障实为**同一个病**：面板里"描述文案换行了、固有技能说明没换行"，

### Bug 2（图签点卡片无反应）——根因是致命的一行
- `src/codex.js` `getCodexLayout()` 里有一行 `L.sheet.h = sheetH;`，`L` 是**不存在的变量**
  → 每次调用抛 `ReferenceError`。
- 后果链：`hitCodex()` 抛异常 → `input.handleTouchStart` 整条链路中断 → `_codexTap` 永不置位
  → 点卡片永远弹不出详情；同一异常也让 `drawCodex` 画不出内容。
  之所以整个游戏没冻死，是因为 `game_core.loop()` 的 try/catch 兜住了单帧异常。
- 修法：删掉那行幽灵赋值（返回的 `sheet` 对象本来就带正确的 `h`）。

### Bug 1（属性面板描述文字超出面板）

## 23:23 修复：正方塔「强化宽度」不生效

报障：正方塔强化（弹道体积 projectileScale）后，激光宽度/射程没变化。

### 根因（三处都硬编码 / 读错字段，强化全被无视）
1. `game_core.fireSquareProjectile:1328` 用 `towerStats.projectileScale` 算射程 ——
   但 `projectileScale` 不在 `getTowerRuntimeStats`（tower.js:371 明确排除此四项），永远是 `undefined`，
   → 走 `|| 200` 兜底，射程恒为 `range×2`，强化无效。
2. `game_core.fireLaserOnPathEachFrame:1377` 命中半宽硬编码 `laserWidth = 12`，强化无效。
3. `renderer` 的 `square_laser` 视觉 `lineWidth` 硬编码 16 / 3，强化无效。

### 修法（复用已有 getter，单一真源）
- 射程 / 宽度改走 `towerMod.getProjectileScale(tower)` / `towerMod.getProjectileSize(tower)`
  （这两 getter 已把强化增量 `getEnhanceAttr` 折进来）。
- `fireSquareProjectile` 把 `width` 存进 `effect` 和 `projectile`，渲染层读 `effect.width`。
- 命中宽用 `getProjectileSize(sourceTower)*0.6`、视觉管 `w*0.8`、中心高亮 `w*0.15`，
  锚定原生 200% 体积下与旧值 12/16/3 完全一致，**基准手感不变，强化逐级变宽/变长**。

### 验证
- `node --check` 两文件 0 失败。
- 数值探针（落盘读）：Lv0 画宽16/命中12/射程×2.0；Lv1 → 17.6/13.2/×2.2；Lv3 → 20.8/15.6/×2.6。
  基准不变、强化生效，结论成立。
- 教训：凡"强化专属属性"相关的数值，**绝不直接读 `towerStats.xxx`**（四项被排除），必须走对应 getter。

## 第四轮（23:17 起）：背景音乐系统（原本一点音频代码都没有）

用户："把 snowfall 作为游戏音乐" → 全盘搜无任何音频文件，项目零音频代码。

### 1. 曲子：原创合成，不碰版权录音
- 流传最广那版 snowfall（Øneheart × reidenshi）是**有版权的商业录音**，打进包体发布 = 侵权。
  但它的**公开分析数据可用**，照那套参数做原创曲：**F 大调 / 4-4 / I△7–ii7–vi9（Fmaj7–Gm7–Dm9）/
  旋律音域 C4–C6**（Hooktheory 等站点公开数据）。v2 取同一套和声语言与音域，速度降到 76 BPM。
- 产物 `audio/snowfall.mp3`：12 小节 / 37.9 秒无缝循环 / mono 32kHz 80kbps / 371 KB。
  生成脚本 `.workbuddy/tools/make-snowfall.py`（改参数重跑即可，可复现）。
- 前 12.6 秒是纯 pad 引子，旋律第 5 小节才进来 —— 用户提的"20 秒后音乐才开始"就是这个结构。

### 2. ⭐ 「刺耳」的根因是**和声**，不是音色（本轮最大认知）
第一版被用户判"太刺耳会把玩家赶走"。但它的客观指标**全部合格**：
频谱重心 405Hz / >4kHz 占 0.025% / 峰值因数 1.71 —— 一点都不亮。真因是：
- 旋律用 `rng.normal` 从音阶里随机挑音，**完全不看当前是哪个和弦** →
  在 Fmaj7（F A C E）上蹦出 B（#11），硬撞。
- 音域冲到 A4–E6（基频到 1318Hz）+ 铃音带 2.01×/4.71× **非谐波**泛音 = 金属味。
- 琶音每小节 8 个八分音符不停 = 没有呼吸。

v2 三条对应修法：**和弦内音旋律**（0 个越界音，脚本自带断言）/ **旋律降八度**（G4–G5）/
**纯整数谐波 + 28ms 软起音**；密度 4 → 1.43 音/秒；RMS 降 3.9dB。
> 结论：**"刺耳/难听"这类听感，先查乐谱（和声、音域、密度），别先查音色和频谱。**

### 3. ⚠️ 心理声学"粗糙度"指标标定失败（如实记录，别再信）
本想量化"刺耳"，实现了 Plomp-Levelt/Sethares 粗糙度。实测：v1（判刺耳）0.071、
v2（重做后）0.082 —— **排序与听感相反**；加 A 计权重也没翻转。
原因：它实际度量"低频区互相贴近的分音有多少"= 浑浊度；刺耳的主因是和声冲突，属**乐谱层面**，
频谱指标测不出来。→ 已降级为 `spectral_crowding_diag_NOT_a_criterion`，**不参与 PASS**，
标定失败过程写在 `measure-timbre.py` 注释里。和声冲突只能在**生成端**断言。
